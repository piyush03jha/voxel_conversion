# Contextual Voxel3D links

Formshift remains an independent converter. A small navigation link and footer attribution clearly identify Voxel3D. The optional printing next step appears after a completed STL/3MF result, below the ordinary download action; batch/package shows it once after a printable-format result. Links go to the existing ADVFX /custom page (confirmed in source, live route not verified here), in a new tab with noopener/noreferrer. No model transfer, identifiers, filename, size, account data, analytics cookies, popups, queue ads or product cards. UTM tags contain fixed placement values only. Clicking is optional. Conversion success does not establish printability.

Six genuine format guides have working converter/compressor settings. A matching input selects the documented output; incompatible input remains selectable with an explanatory message. The guide content is served as static HTML in production and the React app replaces it with the interactive workspace. Build with VITE_SITE_ORIGIN set to the final converter HTTPS origin (not voxel3d.org unless actually hosted there) to produce canonical URLs and sitemap.xml. No origin guessed. Host nested index.html routes and keep SPA fallback for /compress, /batch, /package and related routes. Submit sitemap after live service verification. Do not create thin pages for every theoretical format pair. No SEO or traffic guarantee.

No ADVFX edits or new dependencies. Direct file transfer would require a separately reviewed, explicitly consented cross-site integration; deliberately not included. No analytics ingestion is installed; UTM attribution is available only if destination analytics records it. Run npm run build and inspect generated guides, links, mobile header, completed STL/3MF and nonprintable outputs. Test navigation while processing; links open a new tab.
