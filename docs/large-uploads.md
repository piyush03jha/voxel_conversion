# Large upload and worker changes

ADVFX main inspected at 94dd953772725db967b7e58126d15ff67f1e085e. Native dense mesh and 3MF scripts copied byte-for-byte from that revision, including the STL exact-weld fallback to unindexed streaming and memoryview output writes. No writes to ADVFX. Retain independent anonymous job tokens and Redis queue.

- No fixed application file-size cap in the browser, API or worker. Nonempty safe-integer sizes must fit the S3-compatible object protocol (up to 5 TiB); actual storage provider limits apply. The shared outstanding/retained input reservation budget defaults to 32 GiB across jobs (TEMP_INPUT_BUDGET_GIB). It is adjustable, not a guarantee of free storage. Existing output bytes are not included in this input quota; monitor total storage.
- Files up to 32 MiB keep the signed conditional single PUT. Larger files use S3 multipart: 16 MiB minimum part size, scaled to fit 10,000 parts, 3 parallel transfers, fresh signed part URLs on demand, per-part bounded retries. The server lists authoritative parts and verifies their lengths and sequence before completing, then HEAD verifies total size/ETag. The worker reads only that ETag, streams to disk, and enforces declared length. The existing session ID remains the queue job ID. Failed/expired sessions abort multipart uploads in the sweeper; configure provider lifecycle to abort incomplete multipart uploads after one day. A lost multipart-create response can orphan parts until that lifecycle runs. No file bytes in API/Redis.
- Existing browser conversion/preview limits remain deliberate (10 MiB). Server preview source no longer has the 200 MiB limit. Processing can fail at actual disk, geometry, archive, process memory and format bounds. Before downloading, reserve input + 3*configured maximum output + disk headroom using statfs; this conservative per-worker preflight is not a cross-container disk reservation.
- Worker RAM-aware optimizer heap (35%, capped 4096 MiB), native process address space (50%, capped 4096 MiB), triangle budget derived from native limit, 30-minute timeout by default, output limit defaults 1024 MiB (configurable up to 4095 MiB; GLB itself uses 32-bit length). Keep one active job per worker. Existing env overrides take precedence. Archive limit and sandbox remain enforced. Native STL may preserve more geometry than the previous fixed weld limit; large valid models still need benchmarks.
- GLB High compression uses 80% static geometry retention and 1024px texture maximum instead of aggressive 30%; Low/Medium do not simplify, None remains uncompressed. No fixed target output size. Existing 3MF repack preserves entries.
- The standalone converter still expires original and output objects under its temporary retention policy; do not copy ADVFX catalog database or permanent storage behavior. No automatic public deployment approval.

## Test locally
Restart API and workers together (heartbeat v5). Update .env from .env.example selectively (remove old fixed WORKER_OPTIMIZER_HEAP_MB, WORKER_PROCESS_MEMORY_MB and WORKER_MAX_TRIANGLES if automatic sizing is desired). Use one worker, confirm host disk and memory. Run npm run infra:up (multipart compatibility probe), npm test, npm run test:browser, npm run test:native, npm run build, then test an actual 300 MiB file and interrupted multipart uploads. For R2, configure exact origins, PUT/GET/HEAD, required headers, lifecycle expiry and incomplete multipart abort. Provider-specific limits, CORS, signature enforcement, disk capacity, multipart completion/recovery and real large conversions require runtime verification before public use.
