# Batch processing

Update: [Model packages](model-packages.md) supersedes the OBJ/glTF-only dependency and package compression limitations below. Worker heartbeat v7.

The converter remains independent of ADVFX. Batch conversion (/batch) and batch compression (/compress/batch) reuse the existing single-model engines, multipart uploads, private temporary storage, and Redis queue. API validation and the worker contract reject mixed conversion + compression requests. Conversion always uses None; compression keeps the input format. Old combined-job API clients must be updated. Stop old workers/API and drain or cancel older incompatible jobs before restarting (heartbeat v6).

## Workflow
- Select multiple files, a folder, or ZIP archives. Browser scans classic/ZIP64 stored and deflated entries, including nested ZIPs up to two levels, and preserves relative paths. 3MF/USDZ are treated as models, not generic ZIPs.
- Up to 100 models and 5000 entries, 1 GiB cumulative expanded ZIP data, 200:1 expansion ratio for entries over 8 MiB, path/duplicate/encryption/symlink and CRC checks. Direct standalone files retain the existing no-fixed-byte-cap policy, subject to storage/resources. ZIP metadata is limited to 8 MiB; UTF-8/ASCII filenames are required. Password-protected, multi-disk and non-ZIP formats are rejected. Browser private disk (OPFS) is preferred for extraction; fallback buffers at most 64 MiB per scratch store. No additional npm dependencies.
- Detect OBJ mtllib and common MTL map references plus glTF external .bin/image URI references. Preserve relative paths and send only that model and its dependencies as a private ZIP64 bundle. The worker extracts one selected model in its sandbox, revalidates paths, entries, expansion and references, and invokes Blender directly. MTL map options, continued lines, remote references, missing assets, glTF manifests >8 MiB with external resources, and external dependencies of other model formats are not guaranteed. OBJ output still has the existing geometry-only/no MTL limitation; GLB is recommended when materials matter.
- Choose a common target or a per-model compatible target. Browser-supported standalone small jobs run locally; all other jobs use existing workers if allowed. Batch compression supports same-format GLB/STL/OBJ/PLY/3MF, with external-dependency OBJ bundles explicitly skipped (cannot guarantee original material/texture preservation). Unsupported formats or incompatible targets are individually reported. No automatic conversion plus compression.
- Owner-only batch token in Redis, with atomic one-outstanding-server-job guard. Completed, failed or cancelled jobs release the next item; standard jobs join existing FIFO, preview remains lower priority. One active model per worker. This provides fairness between batch sessions, not identity-based fairness (anonymous users may open multiple batches). No server-side background coordinator: the tab schedules each next file; keep it open. Interrupted tracking retains the current session in memory for resume; refresh loses tokens. Stop after current lets the active job finish.
- Download each completed output immediately. Batch server downloads get safe original-derived filenames. Download-all collects only completed results via signed GET, streams them to browser private disk, and creates a ZIP64 archive from file-backed Blob parts without loading all server models into RAM. Results already retrieved are cached for repeated packaging; failed/expired downloads are reported. The packaging decision avoids an additional server worker or storage upload. Wait until downloads finish before clearing the batch. Scratch data is deleted on clear/unmount where possible; abandoned directories older than 48h are removed on a later visit. Existing server expiry and lifecycle apply. The final ZIP is stored (not recompressed), with uniquely numbered output names; geometry compression is a separate operation.

## Test
```bash
npm run test:batch
npm test
npm run build
npm run lint
npm run smoke:batch
```
Smoke batch needs a configured local API with queue admission enabled and either a worker or queue-only test mode. Browser tests cover ZIP64 and dependency detection; Python tests cover extraction. Verify live multipart uploads, large OPFS extraction, browser download-all, multiple simultaneous batches, owner tokens, expiry/cancellation, and Blender import of real dependency bundles before public launch. No claim of full production integration verification. Public conversion remains disabled by default.

## Authoring verification
The exact committed ZIP64 module and shared path/key module were independently compiled with TypeScript 5.8.3. Eight Node 22 ZIP checks passed (ZIP64, classic deflate, nested ZIP, third-level rejection, unsafe paths, expansion ratio, duplicate names and CRC), and Python successfully read the generated ZIP64 archive. Six dependency discovery cases passed against the exact discovery source with the existing format-detection function mirrored in the isolated harness. Nine Python extraction cases passed with the exact committed extraction source. Ten path and two key checks also passed. These are source-level/isolated tests, not full React/NestJS, Redis, browser OPFS, storage or Blender integration. Repository network and Docker are unavailable in the authoring shell; run the listed tests locally.
